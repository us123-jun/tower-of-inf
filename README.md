# 무한의 탑 · 친구들과 공유하기

서버 설치 없이 GitHub Pages에서 실행되는 픽셀 RPG입니다. 플레이어마다 자기 브라우저에 진행을 저장합니다.

## 가장 쉬운 배포: 업로드용 ZIP

`tower-github-pages-upload.zip`을 받은 경우 다음 순서대로 진행하세요.

1. GitHub에 로그인하고 [새 저장소 만들기](https://github.com/new)를 엽니다.
2. 이름을 `eternal-spire`처럼 정하고 **Public**으로 만듭니다.
3. ZIP을 풀고 그 안의 파일과 `assets` 폴더를 **Add file → Upload files**로 올립니다. ZIP 파일 자체를 올리지 마세요. 저장소 최상위에 `index.html`이 보여야 합니다.
4. **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/(root)**로 선택하고 Save를 누릅니다.
5. 배포가 완료되면 Pages에 표시되는 주소를 친구들에게 공유합니다. 보통 `https://내아이디.github.io/eternal-spire/` 형태입니다.

업로드용 ZIP에는 GitHub Actions 파일을 넣지 않았으므로 위의 브랜치 배포 설정을 사용합니다. 파일을 수정해서 같은 저장소에 커밋하면 GitHub가 다시 배포합니다.

## 소스를 직접 수정하면서 자동 배포: 소스 ZIP

`tower-github-source.zip`에는 게임 소스, 검사 스크립트, GitHub Actions 설정이 들어 있습니다.

1. 새 Public 저장소를 만듭니다. 기본 브랜치는 `main`을 사용합니다.
2. ZIP을 풀어 **내용 전체**를 저장소 최상위에 올립니다. `index.html`, `assets/`, `scripts/`, `tests/`, `.github/workflows/pages.yml`이 들어가야 합니다. 숨김 폴더인 `.github`도 빠뜨리지 마세요.
3. **Settings → Pages → Source**를 **GitHub Actions**로 선택합니다.
4. **Actions → Deploy game to GitHub Pages → Run workflow**로 첫 배포를 실행합니다. Pages 설정 전 실행이 실패했어도 설정 후 다시 실행하면 됩니다.
5. 이후 `main`에 업데이트하면 검사 → 파일 빌드 → 배포를 자동으로 실행합니다. 성공한 작업의 `github-pages` 주소를 공유하세요.

업로드용 ZIP과 소스 ZIP은 배포 방식이 다릅니다. 한 저장소에서는 선택한 방식 하나를 사용하세요.

개발 시 Node.js 22 이상만 필요하며 외부 패키지를 설치하지 않습니다.

```sh
npm test
npm run build
```

배포 파일은 `_site/`에 만들어집니다. 저장소에는 `_site/`를 올리지 않습니다. CSS·JS·이미지·글꼴 주소에는 내용에 따른 버전이 붙어 업데이트 후 이전 파일이 캐시에 남는 문제를 줄입니다. `_site/`에는 게임 공개 파일만 포함하며 Git 정보나 호스팅 설정·인증 정보는 포함하지 않습니다.

## 업데이트해도 진행을 유지하는 방법

- 같은 GitHub 저장소·Pages 주소를 유지하고 게임 파일을 덮어씁니다. 새 버전마다 새 저장소나 새 도메인을 만들 필요가 없습니다.
- 저장 키 `eternity-stages-v2`를 바꾸거나 `localStorage.clear()`를 실행하지 마세요. 코드와 저장 데이터의 버전은 별개입니다.
- 저장 키와 기존 필드 이름은 유지합니다. 새 필드는 기본값을 채워 이전 저장을 이전합니다. 필드를 바꾸거나 없애야 한다면 기존 저장을 새 구조로 옮기는 코드를 먼저 추가하세요.
- 기존 플레이어가 이미 가진 레벨, 장비, 스킬, 마을, 재화는 기본값으로 덮어쓰지 않습니다. `tests/upgrade.test.mjs`가 실제 게임 코드로 이전 저장의 보존을 확인합니다.
- 저장 형식을 호환되지 않게 바꿀 때는 `saveSchemaVersion`과 `storage.js`의 스키마 처리·이전 코드를 함께 바꾸세요. 지금은 저장 스키마 1입니다. 단순 콘텐츠 업데이트 때 스키마 번호를 올리지 않습니다.
- 자동 백업은 같은 브라우저에 저장되며 세션 중 최대 1분 간격으로 이전 저장을 보관합니다. 주 저장이 읽히지 않으면 백업 복구를 시도합니다. 마지막 백업 이후 진행은 일부 빠질 수 있습니다.
- 다른 탭에서 저장이 바뀌면 오래된 탭의 쓰기를 멈춥니다. 안내가 나오면 새로고침해 최신 진행을 불러오세요.
- 더 최신 형식의 저장이나 읽을 수 없는 원본은 새 게임 데이터로 덮어쓰지 않습니다. 화면의 저장 안내를 확인하고 업데이트 또는 백업 가져오기를 진행하세요.

## 지금 HTML 파일에서 하던 진행을 처음 옮길 때

다운로드한 파일과 GitHub Pages는 서로 다른 저장 공간입니다. 한 번만 저장 파일을 옮기면 됩니다.

1. 기존 HTML을 열어 **보상 → 진행 저장 관리 → 저장 내보내기**를 누릅니다.
2. GitHub Pages 주소로 접속합니다.
3. **보상 → 진행 저장 관리 → 저장 파일 선택 → 선택한 저장 적용**을 누릅니다.
4. 이후 그 주소에서 플레이하면 같은 브라우저에 계속 자동 저장됩니다.

마을 추가 이전 저장 파일도 불러올 수 있습니다. 기기·브라우저·도메인을 바꿀 때도 위의 내보내기/불러오기를 이용하세요.

## 저장 범위

GitHub는 게임 파일을 배포합니다. 플레이어 진행은 각자의 기기·브라우저에 저장되며 서로 공유되지 않습니다. 로그인이나 서버 동기화는 이 버전에 포함되어 있지 않습니다. 사이트 데이터 삭제나 시크릿 모드 종료로 저장이 사라질 수 있으므로 중요한 진행은 JSON으로 내보내 두세요. 저장 파일을 GitHub 저장소에 올릴 필요는 없습니다.

무한 탑/동굴, 자동 원정, 장비·전설 무기, 스킬 이펙트, 마을 건설을 포함합니다. 직접 전투는 WASD/방향키 또는 터치 드래그로 이동하고 자동 공격합니다.

자동 저장·백업·업데이트 이전과 배포 빌드 검사를 포함합니다. 실제 GitHub 업로드 및 배포는 저장소를 만든 뒤 위 설정을 완료해야 하며, 로컬 검사만으로 실제 배포 성공을 보장하지는 않습니다.
